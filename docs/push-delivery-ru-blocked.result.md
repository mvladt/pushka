# Результат: диагностика недоставки push-уведомлений (блокировка FCM в РФ)

## Проблема

Уведомление, запланированное через демо-клиента (`pushka.mvladt.ru`), стабильно не доходило до
браузера, хотя сервер репортовал успех.

## Диагностика

Живая сессия: слежка за `journalctl -u pushka -f` на SPB параллельно с созданием тестового
уведомления через демо-страницу.

1. **Сервер отправляет успешно.** Лог показывает `Notification sent. Status: 201` — `web-push`
   достучался до FCM (`https://jmt17.google.com/fcm/send/...`), и Google принял сообщение.
   `201 Created` — стандартный ответ push-сервиса «принял, дальше доставлю сам». То есть код
   pushka (`src/pusher/pusher.ts`) и сеть сервера (SPB) ни при чём — проблема за пределами
   зоны ответственности бэкенда.
2. **Через локальный SOCKS5-прокси (127.0.0.1:1080, выход через AMS) уведомление дошло.**
   Тот же сценарий (новая подписка в чистом профиле Chrome, `--proxy-server=socks5://127.0.0.1:1080`)
   — push появился в списке «Получено» на странице в течение секунды после отправки сервером.
3. **У прокси-подписки другой endpoint.** Подписка, созданная без прокси (обычный профиль),
   получила `https://jmt17.google.com/fcm/send/...`. Подписка, созданная **через прокси**,
   получила `https://fcm.googleapis.com/fcm/send/...` — другой шард FCM. То есть шард
   назначается Google в момент `pushManager.subscribe()` в зависимости от сети клиента, а не
   зависит от того, откуда сервер потом шлёт `POST`.

## Вывод

Причина — не в pushka. Похоже на блокировку/дросселирование конкретных шардов FCM
(`jmt17.google.com` и подобных) на уровне провайдера/ТСПУ (аналогично истории с недоступностью
GitHub Actions → SPB по SSH, см. диагностику деплоя от 2026-07-27). Основной домен
`fcm.googleapis.com`, судя по всему, не блокируется, а региональные/legacy-шарды — блокируются
по IP-диапазону. Какой шард достанется браузеру — решает Google на этапе подписки, в зависимости
от сети, из которой пришёл запрос `subscribe()`.

## Не проверено / не сделано

- Не проверено, продолжит ли подписка с `fcm.googleapis.com` доставлять уведомления **без**
  прокси (то есть закрепляется ли шард за подпиской надолго, независимо от сети получения) —
  тестовый Chrome-профиль с этой подпиской остался поднят, тест не завершён.
- Нет решения на стороне продукта: это принципиально внешний фактор (сеть/провайдер конечного
  пользователя), pushka не может ни определить шард заранее, ни повлиять на его выбор.
- Не решено, стоит ли где-то предупреждать пользователей демо (например, в `src/client/index.html`)
  о том, что при недоставке уведомлений в РФ возможен обходной путь через VPN/прокси при первой
  подписке.
