# План: фикс input[type=datetime-local] на iOS Safari (issue #12)

## Контекст

Issue [#12](https://github.com/mvladt/pushka/issues/12): на iPhone (Safari, страница добавлена
на экран «Домой») поле «Время» (`input#input-datetime`, `type="datetime-local"`) в секции
«Запланировать уведомление» рендерится шире колонки и выбивается за её пределы, рамка выглядит
иначе, чем у полей «Заголовок»/«Текст». Ожидание: та же ширина и рамка, что у остальных полей.

Весь клиент — один файл `src/client/index.html` (стили в `<style>` в `<head>`), менять нужно
только его.

## Диагноз

Это известное поведение iOS Safari, а не ошибка в наших стилях:

1. **Ширина.** iOS Safari рисует `date`/`datetime-local` нативным UA-виджетом и при этом
   игнорирует `width: 100%` из общего правила `input { width: 100% }` — инпут получает
   интринсик-ширину виджета и вылезает из контейнера. Стандартное лекарство — снять нативный
   вид: `-webkit-appearance: none` (плюс `display: block`).
2. **Рамка/фон.** Тот же нативный виджет игнорирует `border`/`border-radius`/`background` —
   после `appearance: none` наши правила из общего `input {}` начинают применяться сами.
3. **Пустое поле схлопывается.** После `appearance: none` пустой `datetime-local` на iOS не
   имеет содержимого, и поле теряет высоту (остаются только паддинги). Лечится `min-height`
   на внутреннем псевдоэлементе `::-webkit-date-and-time-value`.
4. **Выравнивание значения.** iOS центрирует значение внутри поля — для единообразия с
   текстовыми полями нужен `text-align: left` на том же псевдоэлементе.
5. **Плейсхолдер.** `datetime-local` в принципе не поддерживает атрибут `placeholder` — пустое
   поле без текста-подсказки это ограничение платформы. Подпись «Время» над полем уже есть,
   в рамках этой задачи ничего не делаем (см. «Вне скоупа»).

## Решение

В `<style>` в `src/client/index.html`, после общего правила `input {}`, добавить:

```css
/* iOS Safari рисует datetime-local нативным виджетом: игнорирует width:100%
   и рамку из общего правила input. Снимаем нативный вид только на iOS
   (@supports (-webkit-touch-callout: none) срабатывает только там),
   чтобы не менять вид виджета в десктопных браузерах. */
@supports (-webkit-touch-callout: none) {
  input[type="datetime-local"] {
    -webkit-appearance: none;
    appearance: none;
    display: block;
  }
}
input[type="datetime-local"]::-webkit-date-and-time-value {
  text-align: left;   /* iOS центрирует значение — выравниваем как у текстовых полей */
  min-height: 1.5em;  /* пустое поле без appearance схлопывается по высоте */
}
```

Пояснения к выбору:

- **Скоуп через `@supports (-webkit-touch-callout: none)`** — устоявшийся способ применить CSS
  только на iOS/iPadOS (свойство поддерживает только WebKit на iOS). Так десктопные
  Chrome/Firefox/Safari продолжают показывать привычный нативный виджет с иконкой календаря —
  минимальный радиус поражения, issue касается только iOS.
- `1.5em` соответствует `line-height` из `body { font: 16px/1.5 ... }` — высота пустого поля
  совпадёт с высотой заполненных текстовых полей (у всех одинаковые паддинги 8px и рамка 1px).
- Правило с `::-webkit-date-and-time-value` вынесено отдельным блоком (не через запятую с
  другими селекторами): браузер, не знающий этот псевдоэлемент, отбрасывает всё правило целиком,
  и нельзя, чтобы он утащил за собой что-то нужное. Вне iOS правило просто не матчится — безвредно.

### Рассмотренная альтернатива

Глобальный `appearance: none` для `input[type="datetime-local"]` без `@supports` — проще, но
меняет вид поля и в десктопном Chrome (виджет теряет часть нативного оформления). Выгоды нет,
риск регрессии есть — отвергнуто в пользу iOS-скоупа.

## Проверка

1. `npm run dev`, открыть страницу в десктопном браузере — форма выглядит как раньше
   (появление регрессий на десктопе = ошибка, см. скоуп через `@supports`).
2. `npx tsc --noEmit` и юнит/интеграционные тесты (`npm run test:env`,
   `npm run test:sqliteStore`, `npm run test:integration`) — должны остаться зелёными
   (изменений в TS нет, это smoke-проверка).
3. e2e `npm run test:playwright` гоняет реальный цикл через Chrome и `page.fill("#input-datetime", ...)`
   (`tests/playwright/push-cycle.spec.ts:75`) — `appearance` на программное заполнение не влияет,
   тест должен пройти. Локально требует реального FCM; если локально недоступно — положиться на
   job `e2e` в CI после пуша.
4. **Финальная приёмка — только на реальном iPhone** (автоматизировать нечем: Playwright в
   проекте настроен на десктопный Chrome, а WebKit-эмуляция Playwright не воспроизводит
   UA-стили нативных iOS-виджетов). После деплоя открыть страницу с экрана «Домой» и сверить
   со скриншотом из issue: поле «Время» той же ширины и с той же рамкой, что «Заголовок»/«Текст»;
   пустое поле не схлопнуто по высоте; тап по полю по-прежнему открывает нативный пикер;
   выбранное значение видно и планирование работает.
